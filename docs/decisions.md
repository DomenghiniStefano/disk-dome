# Decisions

Every product and technical decision with its reason, newest first. A change of direction is a new entry,
never an edit of an old one.

| Date | Decision | Why |
| --- | --- | --- |
| 2026-11-24 | Proposed after a new-user walk-through: one large call to action «Scan C:» (new `hero` button size) instead of a small toolbar button, no scan-mode dialog at first launch (the mode in one line with «Change»), toolbar with global controls only, the layout control and the selection's actions (Show, Move to the Recycle Bin) in Explore's own bar, the map first in Overview, sections ordered by use, plain words in the interface (`docs/design-system.md` § 6.15) | the owner: «it must be intuitive: if scanning is the first thing to do, it can't be a small hidden button» |
| 2026-11-24 | Proposed: a disabled control stays in place with its reason in the tooltip; one file action at a time; every error shown by one component (info bar, toast, inline, empty state) from an engine code; a Tab order by zones and Narrator texts for every element (`docs/design-system.md` § 6.13–6.14, § 7) | the owner asked for the button and flow analysis to cover states, errors and keyboard too |
| 2026-11-24 | Navigation proposed in three levels: drive tabs → six sections in a full-width bar (Overview, Explore, Time, Statistics, Activity, Clean-up; Ctrl+1…6) → in Explore the layout and «Tree · File list»; Back with history; every number outside Explore drills down into it with a filter; «Largest files» becomes Explore › File list. Every control listed in `docs/design-system.md` § 6.12 | the owner asked to fix the flows (before, during and after the scan, how to reach each section) and to cover every single button |
| 2026-11-24 | Proposed: a Statistics section, seven charts, twenty features beyond WizTree (ten for v1), saved scan summaries for compare and history; the «Folders» map style back for large windows | the owner asked for more charts, statistics and features, and to see Folders again now that the window is large; new per-entry fields keep the model at ~74.5 bytes per entry |
| 2026-11-24 | Map names in four options (None, Few, Many, All), Many proposed as default, with two map-only type steps (11 and 10 px); the window sizes 1920 × 1032 and 960 × 600 drawn next to the default | the owner wants as many names as possible in the map, even small ones, and to see a full and a reduced window |
| 2026-11-24 | More views proposed from the same scan data (Overview tab, Rings, map coloured by age, Time and Activity tabs, Windows' space); which ship in v1 is open | the owner wants to go well beyond WizTree with what the MFT and the USN journal already give; nothing needs an extra pass over the disk |
| 2026-11-24 | Three views (Tree, Both, Map) chosen from the toolbar; drive tabs, one per local drive plus closable folder tabs (placement open: title bar, toolbar or own row); free space shown in the map with a checkbox, off by default | the owner wants the map to take the whole window, or the folders only, for anyone to understand it, and to switch drives easily |
| 2026-11-24 | Light theme is a soft grey (surfaces L 0.94), never near-white; a dimmer «Light dim» proposed; Laguna one step darker proposed (L 0.74) | the owner found the first light theme too bright for the eyes and the first Laguna too bright |
| 2026-11-24 | Map style is a setting; seven styles in comparison (Vignette, Diagonal light, Mosaic, Structure, Flat, Cushion, Relief); Tiles, Outline and Folders dropped | the owner wants to choose among several looks, or keep them all in the app |
| 2026-11-24 | Accent: Laguna, a light cyan-teal at OKLCH 190° (`#3dd7cf` dark, `#007c79` light); the app icon takes it; the data categories Dati and Programmi moved to 176° and 222° to stay clear of it | the widest free gap in the Dome family's hues, calm and technical, far from the red of deletion and the amber of warnings; Volt (118°) sat 31° from SoundDome, Fucsia (350°) next to the danger red |
| 2026-11-24 | Design system proposal written (`docs/design-system.md`): tokens, data colours, components, patterns, Kit, checks; open points listed there | first design session with the owner (step 4) |
| 2026-11-24 | The accent is a new Dome colour, a hue no other Dome app uses; three candidates (Laguna 190°, Volt 118°, Fucsia 350°) compared on the mockup | the family is recognised by its primaries: red Isaac, amber Emu, violet Game, green Sound, sky domehub, gold Post, coral Poke, amethyst Note |
| 2026-11-24 | Treemap and extension statistics coloured by file category (12 families, shades for the largest extensions), the same colours in both themes | readable legend, colours stable between scans and drives |
| 2026-11-24 | Step 3: **go** — the project continues | on the owner's desktop C: (3.4 M entries): scan 7.0 s vs WizTree's 22–31 s, 0.40 GB vs 1.6 GB, 99.1% of folder totals identical; the owner chose not to repeat it on the KIOXIA laptop |
| 2026-11-24 | Sizes counted as WizTree does: every hard link shows the file's size, clusters counted once on the first name; size on disk includes named streams (`WofCompressedData`, `$J`) except `$BadClus:$Bad` | measured on the owner's C: (3.4 M entries): 99.1% of folders identical to WizTree, totals within 0.04%; replaces "other links shown with size 0" |
| 2026-11-24 | `cargo deny` reports "unmaintained" crates only among our direct dependencies (`unmaintained = "workspace"`); vulnerabilities still checked on every crate | six such notices (ttf-parser, zvariant, zbus_names, zvariant_derive, pin-utils, chrono) all come through Slint, carry no known vulnerability, and only Slint can replace them |
| 2026-11-24 | Data model indexed by the MFT record number, children in CSR arrays (`child_start` + `children`) instead of renumbering entries so children are adjacent | the parser writes each record straight into its slot from any thread and nothing is copied after; costs 4 bytes per entry plus the few percent of free records; measured 61.5 bytes per entry |
| 2026-11-24 | Read and parse on the same threads (twice the cores, 4 MB chunks), one volume handle per thread | overlaps reading and parsing without a queue; Windows serialises synchronous reads on a shared handle |
| 2026-11-24 | Our own `$MFT` parser, no `ntfs` / `ntfs-reader` / `mft` crate | they allocate per record or per attribute; ours parses in place into the model's arrays |
| 2026-11-24 | `crates/platform` created now, for the process memory the benchmarks report | keeps `#[cfg(windows)]` out of the CLI; the shell actions will join it |
| 2026-11-24 | A file counts its unnamed `$DATA` only; hard links counted once (other links shown with size 0) | first version, to check against WizTree; alternate streams decided on what the comparison shows |
| 2026-11-24 | Branches: `develop` for development, `main` for releases only (merge from `develop` + tag, by the owner) | the owner's usual flow in the Dome projects |
| 2026-11-24 | Licence: GPL-3.0-or-later | an application, so companies use it freely; no closed forks; Slint under the GPL needs no attribution; a commercial licence stays possible (with a CLA) |
| 2026-11-24 | v1: Windows only; macOS after v1, built in CI from day one | the `$MFT` scanner is Windows-only; macOS needs its own scanner, signing and notarisation |
| 2026-11-24 | v1 is complete: analysis plus file-manager actions (`docs/features.md`) | the owner wants a finished tool, not a viewer |
| 2026-11-24 | Administrator rights: scan mode chosen at first launch, changeable in the settings (UAC / service / none); the interface is never elevated | safety of deletions, drag and drop with Explorer, user choice |
| 2026-11-24 | Every action updates the model at once; outside changes come from the USN journal | the view never lies after a delete or a move |
| 2026-11-24 | Name: DiskDome | clear, fits the "word + Dome" family; rejected SpaceDome (planetariums), VolumeDome (sounds like an audio app next to SoundDome), FreeDiskDome (sounds like freeware, blocks a commercial licence), two-word names (break the family's pattern) |
| 2026-11-24 | Language: Rust for the engine and the interface | native code, no runtime, one language |
| 2026-11-24 | Interface toolkit: Slint; no web technology (Tauri / WebView) | lightness is the product's reason to exist; stable 1.x API; typed tokens; live preview. egui and Iced are 0.x; GPUI is not a reference for this project |
| 2026-11-24 | Windows scan: read the `$MFT` directly | 10–50× faster than walking directories |
| 2026-11-24 | Treemap drawn by the CPU into a pixel buffer; wgpu only if profiling asks | redrawn only on resize or zoom; Slint's wgpu integration is behind an unstable feature |
| 2026-11-24 | Compact, data-dense interface | 14 million entries to explore |
| 2026-11-24 | Design system base: EmuDome's structure and checks, NoteDome's principles, rapportino's density | EmuDome is the only one whose rules are checked automatically |
| 2026-11-24 | Repository public on GitHub, CI on GitHub Actions (Windows + macOS) | free runners for public repositories |
| 2026-11-24 | Code and documentation in English; interface text through `@tr()`, English source with an Italian translation | same convention as the other Dome projects |
